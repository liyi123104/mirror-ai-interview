# 评分一致性实验记录

> 数据集：`ai/data/eval/answers.json`（10 条回答，覆盖 1–5 分）
> 脚本：`ai/tools/eval_consistency.py`，每题跑 3 轮，维度固定「技术深度」
> 模型：deepseek-chat（失败时退到本地 qwen2.5:7b）
> 机器：i7-12700H / RTX 3060 6GB

## 指标定义

| 指标 | 含义 |
|---|---|
| 差值不超过 1 分的比例 | 同一题跑 3 轮，最高分与最低分差 ≤ 1 的题目占比（越大越稳） |
| 最大差值 | 所有题里最大的 max−min |
| 与人工平均差 | 3 轮均值与人工标注分的平均绝对差（越小越准） |

## 实验记录

| 版本 | 改动 | 差值≤1比例 | 最大差值 | 与人工平均差 | 结论 |
|---|---|---|---|---|---|
| v1 | 基线：只有口径，无关键点、无双次，温度 0 | 100% | 0 | 0.60 | 保留 |
| v2 | 加「先列关键点再打分」 | 100% | 0 | 0.60 | 不影响分数，但理由更具体，保留 |
| v3 | v2 + 双次评分取均值 | 100% | 0 | 0.60 | 一致性已饱和，双评的意义是兜住偶发抖动 |
| v4 | v3 关掉证据校验 | 100% | 0 | 0.60 | 证据校验只影响置信度，不影响一致性 |
| v5 | v3 + 温度调到 0.8 | 100% | 0.5 | 0.62 | 温度没有想象中致命，但没必要开 |
| v6 | v3 + 口径补「档位锚点」 | 100% | 0.5 | 0.62 | 不加分也不减分，留下当文档 |
| v7 | v6 + 三档手感示例（few-shot） | 100% | 0.5 | 0.70 | **变差，回滚** |
| v8 | v6 + 「有缺点就给 4 分」硬规则 | 100% | 0.5 | 0.67 | a05 修到 4 分，但 a03/a06 掉档，净收益为负，回滚 |

**最终采用 v6（口径 + 锚点 + 关键点 + 双次 + 证据校验，温度 0）。**

## 结论

1. **一致性在这套链路上是「天花板指标」。** deepseek-chat 在 temperature=0 下对同一输入是确定的，
   三轮跑下来分数完全一致，v1 基线直接就是 100%。
   常见资料里引用的「60% → 91%」大多来自更早的模型或更高的温度；本机能复现的最差情况是
   「温度 0.8 时最大差值 0.5」，也就是说这条链路本身就不容易抖。
2. **真正难的是和有经验的人打一样的分。** 基线「与人工平均差」0.60：a05、a09 两条人工 5 分的回答被压到 3 分，
   a01（人工 4）被压到 3 分。模型回避极端值，更愿意落在中间档。
3. **提示词不是万能的。** 试了 few-shot（0.70，更差）和硬规则（0.67，净收益为负）。
   强行拔高会让「布隆过滤器。」这种 2 分回答被压成 1 分，反而更远。
   10 条样本上继续调提示词就是过拟合，停在这里。
4. **可复现的一键命令**：
   ```powershell
   cd ai
   $env:SCORE_KEYPOINTS="1"; $env:SCORE_DOUBLE="1"; $env:SCORE_EVIDENCE="1"; $env:SCORE_TEMPERATURE="0"
   python tools/eval_consistency.py --json ..\logs\eval\final.json
   ```

## 成本

- 单题两维双评 = 4 次调用，约 0.003 元；四维双评 = 8 次调用，约 0.006 元
- 一场八题（出题 + 追问 + 评分 + 复盘）实测：**两维 0.087 元、四维 0.18 元**，`scripts/e2e.ps1` 可复现
- 费用按 `cost_log` 表按场景统计（question / score / report）
