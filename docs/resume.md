## 三、一分钟项目介绍（面试开场用）

> 这是个 AI 模拟面试系统：上传简历、选岗位，AI 按岗位要求出题，顺着你的回答追问，
> 八题之后给四维评分和逐题复盘。
>
> 架构上故意拆成两个服务：Java 管业务和状态——鉴权、面试状态机、事务、报告；Python 管 AI——
> PDF 解析、向量检索、出题评分。两边靠一份内部接口契约和内部令牌通信，Python 不碰数据库，
> 所以它是无状态的，可以加副本。前端只认 `/api`，不知道 Python 存在。
>
> 技术上最想讲的是评分：让模型打分三行代码就够了，难的是每次都打一样的分。我做了五层——
> 把评分口径写成文件、温度归零、先列关键点再打分、四维双评取均值、证据必须是候选人原话。
> 十道题的标注集跑三轮，同一题三次分差不超过 1 分的比例是 100%，和人工标注的平均差 0.6 分。
>
> 另外做了降级：Python 挂了 Java 三秒内返回 5030，不会卡 90 秒；DeepSeek 超时就切本地 Ollama。

## 四、高频追问 & 回答要点

详细版在 `docs/self-test.md`（20 题），这里只给最可能被问的 8 个：

| 追问 | 一句话回答 | 展开方向 |
|---|---|---|
| 为什么拆两个服务？ | 业务要事务和并发，AI 要生态和快速迭代 | 纯 Java 会损失 PDF/向量生态；纯 Python 做状态机事务不划算 |
| AI 服务为什么不连库？ | 无状态才能横向扩容，也避免 AI 侧改坏数据 | 上下文由 Java 在请求里传，几百字节 |
| 一致性 100% 是怎么来的？ | 温度 0 + 确定性模型，同一输入结果一样 | **别吹成"优化出来的"**，见下面红线 |
| 那评分到底强在哪？ | 有依据、可复现、低置信能被标出来 | 证据校验 + 双评差值 + 人工标注集 |
| 追问为什么会跑题？怎么防？ | 模型爱说套话，用"必须引用原话片段"卡 | 短回答 2 字、长回答 3 字，不引用就丢弃重出题 |
| 成本怎么控？ | 维度可配（四维→两维）、并发调用、成本入库可查 | 单场 0.18 元，来源 `cost_log` |
| Python 重启索引没了怎么办？ | Java 启动时全量重推 + 新增增量推 | `StartupSync` + `QuestionService.create` |
| 这个项目最大的问题？ | 评分和人工还有 0.6 差；没做压测；容器没验证 | 敢说缺点比硬吹加分 |

## 五、红线：这些不能写

| 不能写 | 为什么 | 换成 |
|---|---|---|
| "评分一致性从 60% 提升到 91%" | 本机基线就是 100%，这个数字来自模板，说了会被追穿 | "差值≤1 分比例 100%（温度 0），与人工平均差 0.60" |
| "已上线 / 公网可访问" | 没有服务器，没部署过 | "本地完整跑通，容器化文件齐备，待部署验证" |
| "Docker 部署上线" | Docker Hub 拉不到镜像，容器没验证过 | "编写了三个 Dockerfile 与 compose/nginx 编排" |
| "追问引用率 84%" | 那个数字来自资料；我们的实现是规则保证（不引用就丢弃），没有统计模型原始输出 | "追问必须引用原话，不引用即丢弃重出题" |
| 用户量 / 日活 / QPS 实测 | 没有真实用户，没压测 | "单机顺序流程实测：8 题 41 秒" |
